# ПР №5-7. Розробка безпечних мережевих застосунків

## 1. Архітектура та топологія інфраструктури
* **Серверний вузол (`127.0.0.1`):** вебзастосунок на базі **FastAPI + Uvicorn**, який працює у двох режимах:
  * Порт `8080` — базовий нешифрований HTTP-інтерфейс (`/echo-http`, `/health`) для порівняльного аналізу.
  * Порт `8443` — захищений HTTPS-сервер із криптографічним захистом транспортного рівня **TLS 1.3** (самопідписаний центр сертифікації `Demo-Root-CA` та сертифікат сервера з підтримкою SAN `DNS:localhost, IP:127.0.0.1`).
* **Клієнтський вузол (`client/`):** консольний клієнт (`client.py`) та утиліта навантажувального тестування (`bench.py`) на базі бібліотеки `requests` із суворою перевіркою сертифіката кореневого центру (`--ca server/certs/ca.crt`).

## 2. Реалізовані механізми інформаційної безпеки
1. **Автентифікація та зберігання паролів (`server/security.py`, `server/users.json`):** облікові записи зберігаються із використанням адаптивного хешування **bcrypt** (12 раундів з автоматичною сіллю) та розмежуванням ролей (`user`, `admin`).
2. **Керування сесіями на базі JWT:** при успішному вході формується підписаний токен **JWT (HS256)** з обмеженим часом дії (`exp`). При передачі підробленого або простроченого токена сервер повертає `401 Invalid/expired token`.
3. **Багатофакторна автентифікація (`TOTP` / `pyotp`):** реалізовано генерацію 160-бітного секрету, формування URI `otpauth://totp/...` та перевірку одноразових 6-значних кодів за стандартом RFC 6238 при вході (`mfa-login`).
4. **Захист від Brute-Force (`server/ratelimit.py`):** вбудований обмежувач частоти запитів (Rate Limiter) блокує серію невдалих спроб входу з однієї IP-адреси або для одного користувача кодом **`429 Too Many Requests`**.
5. **Журналювання та аудит (`server/logger_setup.py`, `tools/analyze_logs.py`):** усі події безпеки (`auth.ok`, `auth.fail`, `auth.fail.otp`, `rate.limit`) записуються у структурованому форматі JSON та аналізуються скриптом `analyze_logs.py`.

## 3. Порівняння продуктивності (HTTP vs HTTPS) та висновки
* Під час тестування на 100 запитах протокол **HTTPS (TLS)** демонструє дещо вищу затримку (`p50=4.05ms`, `p95=4.72ms`) порівняно з нешифрованим **HTTP** (`p50=1.57ms`, `p95=1.91ms`) через витрати на TLS-рукостискання та симетричне шифрування пакетів, проте забезпечує повну конфіденційність і цілісність даних.
* **Рекомендації щодо розвитку:** зберігання секретного ключа JWT та бази користувачів у захищеному сховищі (PostgreSQL + HashiCorp Vault), перехід на короткоживучі Access-токени в парі з Refresh-токенами та інтеграція автоматизованого сканування (Bandit + pip-audit) у CI/CD.
