# Вимоги до безпеки (Фаза аналізу)

## 1. Область застосунку та модель SDLC
* **Застосунок:** Вебдодаток на базі Flask з аутентифікацією користувачів, пошуком записів і базою даних SQLite.
* **Обрана модель розробки:** **DevSecOps** (безперервна інтеграція перевірок безпеки на кожному етапі життєвого циклу: планування вимог -> моделювання загроз -> SAST-аналіз коду -> DAST-тестування стенду -> аудит).

## 2. Функціональні вимоги безпеки
- **AUTH-1**: Обов'язкова авторизація користувачів для доступу до захищеної сторінки `/profile`.
- **AUTH-2**: Обмеження кількості невдалих спроб входу (Rate Limiting / Lockout) для захисту від підбору паролів.
- **STOR-1**: Паролі користувачів повинні зберігатися у БД виключно у вигляді стійкого криптографічного хешу з використанням «солі» (`werkzeug.security` / PBKDF2-SHA256).
- **LOG-1**: Журналювання подій безпеки (успішні та невдалі спроби входу, підозрілі запити).
- **CONF-1**: Конфіденційні ключі (`SECRET_KEY`) не повинні зберігатися у відкритому вигляді в коді — лише через змінні середовища (`ENV`).

## 3. Нефункціональні вимоги
- **Відповідність стандартам:** OWASP ASVS L1–L2 (базові вимоги до автентифікації, валідації вводу та керування сесіями).
- **Продуктивність:** час проходження автоматизованого SAST-сканування в CI не повинен перевищувати 3 хвилин.
- **Експлуатованість:** наявність регламентованого процесу тріажу вразливостей та їх фіксації у трекері завдань.

## 4. Загрози (огляд)
- SQL-ін'єкції (SQLi) в ендпоінтах пошуку (`/search`) та входу (`/login`).
- Відображений міжсайтовий скриптинг (Reflected XSS) при виведенні неперевірених параметрів (`/echo`).
- Слабка автентифікація (словникові атаки, зберігання паролів у відкритому вигляді).
- Витік секретних ключів або вразливості у сторонніх Python-бібліотеках.

## 5. Цілі безпеки (Тріада CIA)
- **Конфіденційність (C):** захист облікових даних, паролів та даних сесій користувачів.
- **Цілісність (I):** запобігання несанкціонованій модифікації записів у базі даних через SQLi.
- **Доступність (A):** стабільна робота вебсервісу під час навантаження та сканування.

## 6. Початкові ризики
- **R1:** SQLi у модулі пошуку та авторизації → **Критичний (Critical)**.
- **R2:** Reflected XSS при виведенні параметрів → **Високий (High)**.
- **R3:** Зберігання паролів у відкритому вигляді та жорстко зашитий `SECRET_KEY` → **Критичний (Critical)**.
- **R4:** Вразливості у залежностях (`requirements.txt`) → **Середній (Medium)**.
