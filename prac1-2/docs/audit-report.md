# Підсумковий аудит безпеки (SDLC)

## Виконання початкових вимог
- **AUTH-1 / AUTH-2:** Виконано — доступ до `/profile` захищено сесією, додано блокування акаунта після 5 невдалих спроб входу.
- **STOR-1:** Виконано — паролі користувачів у `src/db.py` зберігаються у вигляді стійких хешів PBKDF2 (`werkzeug.security`).
- **LOG-1:** Виконано — додано аудит-логування успішних і невдалих спроб автентифікації через модуль `logging`.
- **CONF-1:** Виконано — прибрано зашитий `SECRET_KEY`, використовується генерація через `secrets.token_hex(32)` або змінну середовища.

## Перегляд змін у коді
- Комміт `chore: init security baseline` — фіксація початкової структури та вимог.
- Комміт `fix(security): patch SQLi, XSS, password hashing and debug mode` — усунення вразливостей у `src/app.py` та `src/db.py`.

## Закриті вразливості
- **R1 SQLi (`CWE-89`):** закрито шляхом параметризації SQL-запитів у `/search`.
- **R2 XSS (`CWE-79`):** закрито шляхом екранування вводу в `/echo` та додавання CSP.
- **R3 Weak Auth / Debug (`CWE-94`, `CWE-256`):** закрито шляхом хешування паролів і вимкнення `debug=True`.

## Ролі та відповідальність у процесі DevSecOps
- **Owner (Власник продукту):** визначає пріоритети релізів та приймає залишкові ризики.
- **Security Champion:** формує вимоги безпеки, проводить моделювання загроз (STRIDE) та тріаж знахідок SAST/DAST.
- **Dev (Розробник):** реалізує функціонал за принципами Secure Coding та виправляє вразливості у коді.
- **QA (Тестувальник):** перевіряє коректність роботи функціоналу після впровадження захисних механізмів.
- **DevOps:** підтримує CI/CD-пайплайни (`sast.yml`, `dast.yml`) та налаштування безпеки середовища виконання.

## Рекомендації щодо подальшого розвитку
- Інтегрувати автоматичне сканування контейнерів (Trivy) та статичний аналіз GitHub CodeQL у CI-пайплайн.
- Винести керування секретами у централізоване сховище (HashiCorp Vault або GitHub Secrets).
